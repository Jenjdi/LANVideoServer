# 阶段 3：本地上传、视频库与浏览器播放

## 功能范围与操作

新增功能项为 **管理员从本地上传视频文件到共享库**。普通用户只能访问已授权的视频和自己的播放位置；当前不提供普通用户的任意文件网盘或私有上传空间。

先构建，使用本机 CLI 一次性初始化自己的管理员，再运行服务：

```sh
cd /workspace/LANVideoServer
bash scripts/setup.sh
./build/lanvideo --init-admin
bash scripts/run.sh
```

浏览器访问实际部署服务的根路径 `/`。默认仅监听本机回环 HTTP，云 onboarding 页面没有回环网页预览。
登录后管理员可在“管理”中选择本地视频上传，或配置已有服务器视频目录并扫描。默认共享目录是数据目录内的 `shared/`。
上传完成后切到“视频库”，点击“授权”，选择已启用普通用户并保存；普通用户登录只能看到这些视频。
点击“播放”后使用浏览器原生控件启动、暂停和拖动。播放位置每 5 秒以及暂停/定位/结束时提交给服务端，刷新页面或重新登录后会恢复已确认保存的位置。关闭标签页的 keepalive 提交是尽力而为，突然断电/网络中断可能丢失最近未确认的几秒。

浏览器管理界面同时提供阶段 2 的创建、禁用、启用、删除、角色与重置密码操作；普通用户只能修改自己的密码。

## 上传协议、限制和取消语义

- `POST /api/media/upload?filename=URL编码的文件名`，管理员会话与 Cookie CSRF 必须有效。
- 正文是单个文件的原始字节，`Content-Type: application/octet-stream`，必须提供一个准确的 `Content-Length`；不支持 multipart、chunked 或压缩上传。浏览器 XHR 自动发送长度。
- 文件名 1–200 UTF-8 字节，不允许路径分隔符、反斜杠、冒号、控制字符或点开头；允许中文和空格。只允许 mp4、m4v、webm、mkv、mov、avi、ogg、ogv、mpeg、mpg、ts、wmv。
- `LANVIDEO_UPLOAD_MIB` 默认 512，范围 1–4096 MiB。非上传正文仍限 8 MiB，认证与其他 JSON 写接口另外限 4 KiB；不会因视频上传扩大普通 JSON 的内存边界。
- 上传直接流入共享目录内随机 `.upload-*` 隐藏暂存文件，不把整个视频保存到请求字符串。校验完整接收长度、容器签名；FFprobe 可用时确认有可读取的视频流并探测时长。这是元数据/视频流探测，不是对全部帧的完整解码或加密完整性证明。
- 完成后 fsync，重新验证会话、权限、共享目录身份和连接状态，再用 Linux `renameat2(RENAME_NOREPLACE)` 发布。重名返回 409，不能覆盖普通文件、符号链接或目录。新上传资源初始仅管理员可见，即使同名旧文件曾有授权，也不会继承旧授权。
- UI 进度来自真实 XHR `progress.loaded/total`。已发送 100% 仍显示等待服务器校验；只有 201 成功结果后才显示上传成功。
- “取消”停止客户端传输。若服务端已经提交完整文件，取消响应等待不能撤销该保存；界面明确提示刷新视频库确认。未接收完毕的上传，以及已收到完整数据但在校验时断开的连接，不会发布文件。两个状态均通过实际测试。
- 空闲读写超时 10 秒；数据接收总时限 120 秒；浏览器请求超时 130 秒。关闭服务可能等到活动请求的读写超时后完成退出，实测未完成上传清理和退出在 15 秒测试上限内。
- 同进程只允许一个上传、扫描或目录修改执行；冲突返回 409，不显示虚构排队进度。正常错误、断开和关闭会清理当前暂存文件。强制 SIGKILL/断电可能留下隐藏暂存文件或已完整发布但未入库的文件，可由管理员检查后重新扫描；不声称文件系统与数据库具有跨介质崩溃原子性。
- 写入或 fsync 失败返回 507；此整文件接口没有实现总磁盘配额或自身断点上传；独立续传见 uploads.md。服务器操作系统账号需要目标目录的读写权限。

## 扫描、授权与路径校验

根目录必须为现有绝对目录，不允许选择整个文件系统 `/`。管理员明确选择的目录别名会解析并保存为规范路径；随后每次打开从文件系统根开始用目录描述符逐级 `openat(...,O_NOFOLLOW)` 验证，包括共享根的父目录。媒体相对路径不能是绝对路径、`..`、隐藏路径或反斜杠路径，只读取普通文件。
扫描跳过符号链接、隐藏项、非视频扩展名和超过目录深度的项目；上限 10000 项、500 个视频和 20 秒（单次正在运行的 FFprobe 最多另耗 2 秒）。探测输出限制 16 KiB、单次内存分配限制 16 MiB，协议仅允许 file/pipe，不通过 shell 拼接文件名。扫描失败不提交半成品目录索引。
FFprobe 缺少时，基础名称、大小、格式仍可用，duration 为 null，metadata_state 为 unavailable。扫描中的无效视频可显示为 invalid，并在浏览器尝试播放时给出解码/读取错误；并不保证所有列出的扩展名或编码可被浏览器播放。

目录变更会清除旧索引、授权和播放历史，重新扫描后默认仅管理员可见。文件的设备号、inode、大小或纳秒修改时间变化时，旧 ID 不能直接继续读取；返回 409 并要求重扫。重扫分配新 ID、清除旧授权和历史，避免将新内容误授给旧用户。此 stat 指纹不是文件内容的密码学校验；本地文件系统管理员仍是受信任角色。
媒体接口只接收数字 ID，不从 URL 拼接文件路径；GET/HEAD 每次重新鉴权、检查媒体授权，并安全打开文件。内容传输按块 pread，持有描述符避免路径被替换后转向其他文件；传输中发现 stat 变化或客户端断开会停止发送。响应头已经发送后的文件变化只能截断传输，客户端应报错后重试/重扫。
媒体列表向普通用户仅返回公开字段，不返回根目录、相对路径或 inode。搜索与格式筛选、数量和分页均基于服务端授权结果。更换账号时前端清理状态，并忽略过期异步列表结果。

## 已实现 API

|方法与路径|权限|请求或结果|
|---|---|---|
|GET `/api/media/config`|管理员|根目录、上传上限、FFprobe 可用状态|
|POST `/api/media/root`|管理员 + CSRF|`{"path":绝对路径}`|
|POST `/api/media/scan`|管理员 + CSRF|空正文或 `{}`；返回真实 indexed/changed/removed/skipped 数量|
|POST `/api/media/upload?filename=...`|管理员 + CSRF|原始文件；201 返回新媒体公开信息|
|GET `/api/media`|登录|`q,format,limit,offset`；只返回已授权结果和 total|
|GET `/api/media/:id`|资源授权|公开元数据及当前用户位置|
|GET `/api/media/:id/grants`|管理员|已授权普通用户 ID|
|POST `/api/media/:id/grants`|管理员 + CSRF|`{"user_ids":[...]}` 原子替换，撤销用户的对应历史同时移除|
|GET/HEAD `/media/:id`|资源授权|视频字节与 Range|
|GET `/api/history`|登录|仅本人的已授权历史，最多 100 项|
|POST `/api/history`|资源授权 + CSRF|`{"media_id":整数,"position":秒数}`|

所有 JSON/SQL 参数均绑定与校验；授予对象必须是已启用普通用户，最多 500 个唯一正整数 ID。
播放位置必须为有限非负数，不超过已知时长 + 1 秒或未知时长的 30 天上限；不允许指定他人的 user_id。

## HTTP Range 的实际约定

- 普通 GET 返回 200、完整字节；HEAD 返回长度和类型但不传输正文。
- 一个闭合、开放或后缀 byte range 返回 206、Content-Range 和准确 Content-Length。越过尾端的结束位置会截断到文件尾，后缀大于文件长度时返回整个文件的 206。
- 不支持多范围，返回 416；无效语法、越界起点、零后缀、空文件的范围请求也返回 416 与 `Content-Range: bytes */实际长度`。
- HEAD 忽略 Range。If-Range 仅支持精确匹配服务端 Last-Modified 日期，其他值回退完整 200；没有实现强 ETag。
- cpp-httplib 0.18.7 会在路由前解析并在路由后再次应用 Range。媒体传输适配层隔离并关闭它的第二次范围切片，以免对已经选择的内容重复截取； malformed Range 的错误路径也重新验证媒体授权。测试覆盖了库处理前后两类错误。
- JSON、HTML 和媒体接口均有 no-store、nosniff、no-referrer、frame 限制；网页 CSP 仅允许本源脚本/样式/媒体，未为浏览器自动化开启 unsafe-eval。

## 实测和未实现

4 个 CTest runner 共 60 项测试全部通过：8 骨架、23 认证、26 媒体/上传、3 真实 Chromium。
真实 MP4 文件完成全文件字节对比、FFmpeg 解码、并发范围对比、超过原 8 MiB 上限的 9 MiB 上传、目录/叶子符号链接防护、授权/撤销、持久化历史、缺失/改变文件、无 FFprobe 回退、断开、校验中取消和活动上传关闭。
Chromium 实际执行文件选择/XHR 上传、授权、普通用户登录、原生 video 解码、定位到 6 秒、暂停保存、刷新恢复，以及重复/无效上传、取消语义、文件名 HTML 注入防护、密码修改和退出。
原始记录保存在 `build/Testing/artifacts/browser-evidence.json`，本次记录的副本为 `docs/browser-evidence.json`；真实页面截图为 `build/Testing/artifacts/admin-upload.png` 和 `viewer-playback.png`。

测试仅采用本机生成的 12 秒、320×180 H.264 MP4，小样本结果不代表公网带宽、所有编解码器、生产性能或安全等级。
容器的 Chromium 沙箱辅助程序不可用，仅在生成的本机测试夹具中使用无沙箱 Chromium，拦截夹具以外的网络请求；未修改系统沙箱或产品部署配置。未进行其他浏览器或移动设备实测。
阶段 3 完成时 BT、BT 代理、分片校验待阶段 4；现已接入，见 bt.md。边下载边播放、远程分享与 HTTPS 反向代理仍待阶段 5–6；HTTP Range 对本地完整文件有效，不表示 BT 分片流播放已实现。
