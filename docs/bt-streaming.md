# 阶段 5：已校验 BT 分片在线播放

新增独立 Bt 分片读取模块，不取消 `.bt-task` 对普通媒体接口的隔离。接口仅供当前任务所有者或管理员，播放记录永远属于当前登录账号。

## 读取流程

HTTP 请求认证、校验任务权限和数字文件索引 → 检查任务处于 downloading/finished/seeding（校验中不可读） → 检查 libtorrent have-piece 位图与 have_piece → 再检查原任务目录身份、无符号链接路径和普通文件 → read_piece 异步读取 → 对整个分片计算 SHA1 并与 v1 元数据对照 → 再次校验路径和权限 → 将不可变内存快照传给 HTTP。跨文件的分片包含相邻文件数据，整个分片一起核对，然后只输出当前视频的字节区域。

每个输出块最多 64 KiB，应用单个分片快照最多 4 MiB（沿用种子分片上限）；同一分片的并发请求合并，最多 16 个待处理分片读取，5 秒清理过期任务。已验证的快照不会因后续磁盘写入而变化。每个输出块重新校验权限、目录和任务 handle；取消任务、重校验或服务关闭终止旧响应。

若首次请求区域在 2 秒内仍不可用，返回 JSON 503、Retry-After: 1 和 retryable=true。读到分片校验失败返回 409、隔离该片，需用户暂停/重校验；不返回稀疏文件里的零或未经检查的字节。中途校验/权限/路径失败时已有响应头无法改成新 HTTP 状态，会终止连接，由浏览器重新请求；不把连接中止伪装成完整文件。

## Range 与映射

设文件在种子内起始字节为 F，浏览器请求视频字节 b，分片长 L，则：

- torrent_byte = F + b
- piece_index = floor(torrent_byte / L)
- offset_in_piece = torrent_byte % L

时间到容器字节的映射由浏览器原生 MP4/WebM 索引完成，服务端根据实际 Range 调度；不把 time/duration × file_size 当作精确映射。客户端也可通过 focus API 提交明确字节位置。

闭合或后缀 Range 返回准确的 206/Content-Range；若涵盖尚未校验区域返回 503，不能偷偷缩短闭合范围。开放 `bytes=b-` 返回从 b 开始的连续可读前缀，单次最多 1 MiB，Content-Range 中总长仍是完整视频长度，客户端继续请求后续范围。无 Range 的完整 GET 只有所有所需片可用时才开始 200；逐片校验输出，不整文件读入内存。HEAD 只返回授权后的元数据，不证明全部内容已可读。非法 Range 为 416，包含真实总长；先重验证授权。BT 流没有稳定 ETag/Last-Modified，If-Range 当前返回 400。

这种原生渐进 Range 方式需要浏览器/编码组合支持；实际已验证的组合及测量结果以最终阶段报告为准，不承诺所有浏览器或编码都能播放。

## 调度与公平性

每次 Range 及显式 focus 提交一个临时窗口：从请求片向后约 1 MiB、最多 128 片，10 秒无请求后恢复常规优先级。每个任务仅保留最新一个焦点，多窗口/多用户同时观看同一任务时最后请求生效。

调度周期 3 秒：2 秒播放窗口优先级 7，1 秒恢复全部窗口片的默认优先级 4；非窗口片一直保留默认 4，不将任何片置零。使用库正常调度，未施加无限 deadline；周期恢复常规调度给其他片提供机会，不声称在无 Peer/限速/拥塞下有绝对时间公平保证。GET schedule 返回真实 libtorrent piece_priority 查询值，phase 是当前应用调度模式。

## API

|方法/路径|作用|
|---|---|
|GET `/api/tasks/:id/files`|仅视频文件；index、相对名称、大小、种子内偏移、已校验字节、连续前缀、隔离状态、自己的播放位置|
|GET `/bt/:id/file/:index`|原生 video 使用的独立受控 Range 入口|
|HEAD `/bt/:id/file/:index`|已授权文件元数据|
|POST `/api/tasks/:id/focus`|CSRF 保护 JSON `{file_index,byte_offset}`；返回映射结果和真实优先级|
|GET `/api/tasks/:id/schedule`|当前窗口和真实优先级，不回显凭据|
|POST `/api/tasks/:id/files/:index/history`|CSRF 保护 JSON `{position}`（秒）；只保存自己的记录|

bt_history 表主键 user_id/task_id/file_index，用户或任务删除时级联清理；重启持久保存。记录不包含令牌或代理凭据。

## 浏览器

BT 下载 → 视频文件 → 边下边播。任务仍需要用户点击「恢复」才联网；播放不会偷偷启动暂停任务。播放器失败时等待两秒查询最新可用情况并重新加载，最多连续自动尝试 30 次（成功播放后重置）；记录当前位置，恢复后继续。暂停任务、校验失败、任务移除、认证失效会给出说明；可以点击重试或在任务页恢复/重校验。浏览器原生控件提供暂停和拖动，编码不支持时提示换用兼容格式。

构建及测试使用现有 CMake/libtorrent/FFmpeg/Playwright，无新增运行依赖。新增测试包含真实部分下载、等待响应、跨分片/跨文件字节、鉴权/CSRF、损坏分片、并发读取、调度周期、关闭取消及浏览器解码。阶段5原生浏览器测试使用 45 秒 640×360 H.264 faststart MP4，零填充；真实 seeder 上传限制 128 KiB/s，记录启动、下载完成率、解码帧、35 秒定位耗时、waiting/stalled 事件和持久化位置。限制出口和小样本不能构成公网性能等级或所有编码兼容性保证。最终原始数据见阶段报告，不填写预设的启动速度或缓冲数。

阶段6重复安装验证发现短夹具可能在首帧前下载完毕，不能作为边下载边播证明。当前浏览器回归改为90秒、640×360、无填充字节的真实视频，保持128KiB/s源限速、45秒起播超时与开始时progress<1断言。最新回归数据见stage6-bt-stream-browser-evidence.json；阶段5的45秒历史记录保留，不把不同夹具的数据合并为性能结论。

播放片调度：焦点阶段使用 libtorrent `set_piece_deadline` 为请求起始片设置 500 ms 调度期限。这是调度目标，不是下载时间保证；后台阶段、焦点变化及租约失效时撤销期限并恢复基准优先级。
