# 本地视频断点续传

阶段 3 的整文件流式上传继续可用。阶段 4 新增独立的持久化上传会话；视频上传与续传仍仅管理员可用，普通用户可自行创建 BT 下载任务。

浏览器：管理 → 选择本地视频 → 勾选「启用分块断点续传」 → 上传。文件逐块计算 SHA-256，每块 1 MiB，最后一块可较短。进度只计服务器已经校验、fsync 并写入 SQLite 的字节。暂停、断网、刷新、服务重启后重新登录并选择**相同内容、文件名及大小**的文件，再次勾选续传并上传。客户端重新计算清单以确认来源一致，查询服务端偏移，从确认的位置继续；不会用文件修改日期判断内容相同。

仅保存非认证信息（账号 ID、文件名/大小/清单指纹和上传编号）到浏览器 localStorage；密码、会话、CSRF、代理凭据不进入 localStorage。上传编号本身不能授权，服务端再次校验登录、管理员角色和任务所有者。成功后清除浏览器记录；浏览器禁用持久存储时刷新后的自动寻找断点不可用，可通过 API 查询已知上传编号。

## API

|方法/路径|输入/行为|
|---|---|
|POST `/api/uploads`|JSON `{filename,size,hashes}`；hashes 是顺序分块 SHA256 小写十六进制数组；返回 201，包含 id、offset、chunk_size、fingerprint、expires|
|GET `/api/uploads/:id`|仅创建者；返回已确认偏移、状态；恢复未确认的尾部写入|
|PUT `/api/uploads/:id/chunk`|raw `application/octet-stream`、一个 Content-Length 和 `Upload-Offset`；必须在 1 MiB 边界且尺寸与清单一致|
|POST `/api/uploads/:id/complete`|所有分块完整后再次逐块核对，计算完整文件 SHA256、检查容器及可选 FFprobe；原子发布并返回 media 与 sha256；已完成重试返回同一结果|
|DELETE `/api/uploads/:id`|删除会话和未发布临时文件；不会删除已发布的视频|

客户端需在网络错误后 GET 查询偏移；未收到响应不等于分块没有被保存。重发已确认且校验一致的分块是幂等的；跳过未确认分块返回 409，错误数据返回 422。未完成文件不进入媒体索引；完整文件默认仅管理员可见，沿用视频授权。

## 持久化与边界

SQLite uploads 表保存 owner、root、name、size、hashes、fingerprint、offset、expires、目录 device/inode、临时文件 inode、state、media_id 和 sha256。数据位于原共享目录内的随机隐藏 `.resume-<id>` 文件，0700 数据目录、0600 文件；保持与目标同文件系统以使用 renameat2 NOREPLACE。分块请求体限制 1 MiB，清单 JSON 限制 300 KiB；单文件沿用 1..4096 MiB 配置。

分块先校验 SHA256，再 pwrite、fsync，最后确认数据库 offset。进程在两步间崩溃的未确认尾部会被截断并重传。完成接口再次核对所有分块和目录身份；支持根据原文件 inode 恢复 rename 后、数据库 commit 前的崩溃窗口。发布冲突不会覆盖已有目标。

有效期为创建后 24 小时，每个管理员最多 5 个未完成会话，进程总计最多 20 个；启动和创建新会话时清理到期及已删除用户的会话。暂停不等于放弃，临时文件继续占用磁盘；可在界面输入断点编号放弃。共享根目录/目录身份变化拒绝继续，需放弃后重新开始。系统不提供后台定时清理或磁盘配额管理；未完成任务的磁盘用量需要管理员管理。

实测：7 项后端测试，以及 Chromium 的真实第二分块连接中断、刷新续传、完整字节与 SHA256 核对。记录在 tests/uploads_integration.py 与 tests/browser_integration.py；没有以随机数或计时器产生上传进度。

清理使用原目录；原路径失效、变为符号链接或文件已被外部删除时，可能需要管理员手动处理残留文件。完成编号表示历史成功发布，后续更改共享目录或删除媒体可能使旧 media_id 失效，请刷新视频库确认。
